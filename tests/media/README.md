# T10 media fixtures

`tests/integration/t10-media.py` generates every sample locally. Nothing is downloaded and no generated bytes are committed. The runner imports it with `importlib.util.spec_from_file_location`; run it and any consumer under `python3 -I` so a file beside generated media cannot shadow the standard library.

## API

```python
generate(base, names=None) -> list
validate_manifest(manifest, allow_hdr=False) -> list
expected_frame(base, asset, time_pos) -> Path
```

`base` is a writable directory. `names` defaults to the nine benchmark samples and accepts either a sequence or a comma-separated string. `hdr` is never included by default. `generate` returns the manifest, also written to `base/media/manifest.json`, and appends every invoked command as one shell-quoted line to `base/commands.log`. A standalone `generate(base, ['hdr'])` writes `base/media/manifest-hdr.json` instead, leaving the SDR manifest intact.

From the repository root:

```sh
base=$(mktemp -d /tmp/t10-media-XXXXXX)
python3 -I tests/integration/t10-media.py --base "$base"
python3 -I tests/integration/t10-media.py --base "$base" --names hdr
```

The first invocation generates all benchmark samples; the second generates and validates only the HDR negative control, not a benchmark input. Both commands return nonzero if any requested asset is unsupported or failed.

Each record has `name`, `status`, `path`, `still`, `sha256`, `still_sha256`, `probe`, and `commands`. `status` is `ready`, `unsupported`, or `failed`. A missing `ffmpeg`, `ffprobe`, or encoder is `unsupported` with an actionable `reason`; it is never reported as success. `validate_manifest` accepts the returned list or a manifest path. It skips explicit unsupported records, rejects failed records, and returns only records whose file, hash, dimensions, codec, command list, and SDR still are valid. HDR is rejected unless `allow_hdr=True`, and that option only permits inspecting the negative control.

`expected_frame(base, asset, time_pos)` accepts an asset record or media path and returns a deterministic PNG under `base/media`. `time_pos` is finite and in `[0, 8)` seconds. It rejects HDR.

## Recipes

All moving pictures use lavfi `testsrc2`, no audio, an exact 8-second duration, and ffmpeg/filter threads capped at 2. Each process also gets a 240-second timeout, a 4 GiB address-space limit, and a 512 MiB output-size limit. `ffprobe -show_streams -show_format -of json` is stored in `probe`. The SHA-256 is of the exact output file.

| Name | Recipe |
|---|---|
| `h264` | 1920x1080, 30 fps, `libx264`, `yuv420p`, `h264.mp4` |
| `hevc` | 3840x2160, 30 fps, `libx265`, `yuv420p`, `hevc.mkv` |
| `vp9` | 1920x1080, 30 fps, `libvpx-vp9`, `yuv420p`, `vp9.webm` |
| `mov` | 1920x1080, 30 fps, `libx264`, `yuv420p`, `mov.mov` |
| `av1` | 1920x1080, 30 fps, installed `libaom-av1` or else `libsvtav1`, `yuv420p`, `av1.mkv` |
| `gif` | 1920x1080, 10 fps, GIF encoder, `rgb8`, infinite loop, `gif.gif` |
| `sar` | H.264 MP4 recipe plus `setsar=4/3`; display width is 2560 after SAR normalization |
| `rotation` | H.264 MP4 recipe copied with stream metadata `rotate=90`; if that does not produce side data, remux with input option `-display_rotation 90`. Accepted only when ffprobe side data reports `rotation=±90` |
| `sdr` | H.264 MP4 recipe tagged `bt709` primaries, transfer, and matrix, TV range |
| `hdr` | 1920x1080, 30 fps, `libx265`, `yuv420p10le`, `hdr.mkv`, tagged BT.2020 primaries, `smpte2084` transfer, and `bt2020nc` matrix. This is a negative control, generated only when explicitly named, and has no still |

Encoder effort is bounded: x264/x265 use `ultrafast` with two worker threads; VP9 uses realtime `cpu-used=8` without row multithreading; AOM uses `cpu-used=8` with one tile and no row multithreading; SVT-AV1 uses preset 12 and `lp=2`.

## Fitted stills

For every non-HDR asset, generation calls `expected_frame(base, asset, 0)` and stores that PNG path in `still`. Frame extraction uses:

```text
ffmpeg -threads 2 -filter_threads 2 -filter_complex_threads 2 \
  -i INPUT -ss TIME -map 0:v:0 \
  -vf scale=round(iw*sar):ih:flags=lanczos,setsar=1,\
scale=1024:768:force_original_aspect_ratio=increase:flags=lanczos,\
crop=1024:768,setsar=1 \
  -frames:v 1 -c:v png -threads 2 -update 1 OUTPUT.png
```

ffmpeg applies tagged rotation before this filter. SAR is then normalized, and the result uses fill mode: aspect-preserving scale up and a centered 1024x768 crop. Output must probe as a 1024x768 PNG. The same function can make a reference at any other valid timestamp; its filename includes a hash of the source path, source digest, and exact time.
